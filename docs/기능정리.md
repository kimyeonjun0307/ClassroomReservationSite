# 강의실 예약 시스템 - 역할별 기능 정리 (v3)

> 이 문서는 지금 실제로 동작하는 기능을 역할별로 정리한 것입니다. DB/RLS까지 이미 다 반영되어
> 배포된 상태 기준입니다 (v2에서 "예정"이었던 항목들은 이번에 실제로 구현 완료했습니다).
>
> **v2 → v3 변경점**: 건물 등록, 가입 승인 흐름을 실제로 구현. `assistants.building_id` 삭제 완료.
> 완료된 후보 기능을 4번 목록에서 제거하고 새로 발견한 미구현 기능 추가.

---

## 0. 역할 3단계

| 역할 | 코드상 이름 | 화면 | 관리 범위 |
|---|---|---|---|
| 예약자(조교) | `assistant` | index.html (메인) | 본인 예약만 |
| 중간관리자 | `mid_admin` | manager.html | 본인이 배정받은 강의실만 (건물 무관) |
| 최종관리자 | `final_admin` | admin.html | 전체 건물 / 전체 강의실 (총괄) |

가입 직후엔 전부 `assistant`로 시작. 다른 역할이 필요하면 **가입 신청 → 최종관리자 승인** 절차를 거침
(아래 1-1 참고). 최종관리자는 건물에 종속되지 않고 시스템 전체를 관리합니다.

---

## 1. 회원가입 / 로그인 (공통, login.html)

- 회원가입: 이름(선택) / 이메일·비밀번호(필수) / 가입 유형(예약자·중간관리자·최종관리자) 입력
  - **예약자**로 가입하면 즉시 사용 가능
  - **중간관리자·최종관리자**로 가입하면 `role_requests`에 "승인 대기" 상태로 접수되고,
    승인 전까지는 예약자 권한으로만 로그인됨 (가입 화면에서 바로 관리자 권한을 주면 보안 구멍이라
    승인 절차를 넣음)
- 로그인: 이메일/비밀번호만 입력. 역할을 따로 고르지 않고, 로그인 성공 시 DB에 저장된 실제 role
  기준으로 index.html / manager.html / admin.html 중 하나로 자동 이동
- 아이디 저장(로컬 기억), 로그아웃

---

## 2. 예약자 (메인 화면, index.html / mypage.html)

- 조건 검색: 건물, 공간유형, 기자재, 최소 수용인원
- 검색 결과 목록 + 층별 필터. **담당 중간관리자 배정 여부와 무관하게 해당 건물의 강의실 전부 노출**
- 강의실별 예약 현황을 날짜 단위 타임라인으로 조회
  - 표시 구분: 정기수업(회색, 예약불가) / 다른 사람 예약(회색, 상세 비공개) / 내가 신청한 것(노란색)
- 강의실 상세정보 확인: 수용인원, 보유 기자재, 이용수칙, 문의처(담당부서/전화/이메일)
- 일일 대여 신청: 날짜+시간대 드래그 선택, 대여목적, 이용인원 입력 후 신청
- 즐겨찾기 등록/해제, "즐겨찾기만 보기" 필터
- 마이페이지
  - 내 예약 목록, 상태별(대기/승인/거절/취소/완료) 필터, 예약 취소
  - **회원정보 수정**: 이름 변경, 비밀번호 변경

---

## 3. 중간관리자 (manager.html)

- 담당 강의실 목록 + 층별 필터 (본인에게 배정된 강의실만, 건물 무관)
- 담당 강의실 전체를 날짜 단위 타임라인으로 조회
- 예약 건 승인 / 거절 (+ 코멘트)
- 승인 대기 목록 한 번에 모아보기
- 담당 강의실 정보 수정: 강의실명, 수용인원, 이용수칙, 문의처(담당부서/전화/이메일)
- 정기수업(고정 시간표) 등록: 학기 선택, 강의실, 요일×시간(복수 가능), 과목명, 담당교수, 수강인원

---

## 4. 최종관리자 (admin.html, 전체 총괄)

- **가입 승인**: 중간관리자·최종관리자로 가입 신청한 사람 목록 확인, 승인/거절
- **건물 관리**: 건물 등록(이름/문의처/기자재 사용여부), 수정. 개수 제한 없음
- **강의실 관리** (전체 건물 대상)
  - 추가 (건물 선택, 층, 호실번호, 강의실명, 공간유형, 수용인원)
  - 상태 변경: 사용가능 / 공사중 / 리모델링예정 / 사용중지
  - 숨기기 (소프트 삭제 — 예약 기록 보존을 위해 완전삭제는 안 함)
  - 담당 중간관리자 배정 현황 확인 (건물별로 그룹핑되어 표시)
- **중간관리자 관리**
  - 기존 assistant 계정을 mid_admin으로 승격 + 담당 강의실 배정 (건물 무관, 체크박스로 다건 선택)
  - 담당 강의실 권한 수정, 담당 해제(계정 삭제 아님 — role을 assistant로 되돌림)
- **학기 관리**: 학기명/시작일/종료일 CRUD (모든 중간관리자에게 공통 노출)

## 5. 아직 없는 기능 (후보)

- 공간유형(room_types)/기자재(equipment) 마스터 관리 화면 — DB엔 있는데 추가/수정 UI 없음 (지금은 고정 4종/4종)
- 예약 승인/거절 이력(`booking_logs`) 조회 화면 — 데이터는 쌓이는데 보여주는 화면이 없음
- 가입 신청 본인 취소 기능 — 신청한 사람이 본인 신청을 취소하는 기능 없음 (최종관리자가 거절하는 것만 가능)
- 이메일 변경 — 지금은 Dashboard(Authentication → Users)에서만 가능, 앱 내 자기 이메일 변경 기능 없음
- 알림 기능 — 종 아이콘만 있고 실제 알림 로직 없음
- 통계/대시보드 (건물별/강의실별 이용률 등)
- `bookings.status = 'done'` 자동 전환 — pg_cron 스케줄이 실제로 등록됐는지 확인 필요
  (마이그레이션 파일엔 함수만 있고, `cron.schedule(...)` 등록은 SQL Editor에서 수동 1회 실행이 필요했음)

## 6. 실무에서 겪은 문제들 (참고용 - 계속 누적 중)

- 프론트에서 새 로그인 계정을 직접 만들 수 없음 (서비스 키를 브라우저에 둘 수 없어서) →
  "계정 생성"과 "권한 부여"는 항상 분리된 단계. 이번에 만든 가입 승인 흐름도 같은 이유
- RLS로 막힌 UPDATE는 에러 없이 0건 처리됨 → `.select()`로 반영 건수 확인하고 실패 시 알림 띄우는
  패턴을 전 화면에 적용함
- PostgREST는 두 테이블 사이에 FK가 2개 이상이면(예: `rooms.manager_id`+`favorites` 경유,
  `bookings.requester_id`+`bookings.reviewed_by`) `테이블명(컬럼)` 형태로 embed 시 "관계가
  여러 개라 모호하다"는 에러를 냄 → `테이블명!fk컬럼명(컬럼)`으로 명시해야 함
- `auth.users.email`을 Table Editor로 직접 고치면 `auth.identities`가 안 맞아서 로그인이 옛날
  이메일 기준으로 계속 동작함 → 이메일 변경은 반드시 Authentication 패널이나 `auth.updateUser()`로
- 계정 삭제는 예약/학기/정기수업 등이 그 계정을 참조하고 있으면 FK 때문에 막힘 → `is_active=false`로
  비활성화하는 게 정석 (로그인 시 앱에서 바로 튕겨내도록 이미 구현됨)
